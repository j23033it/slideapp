# 要件定義

アプリ名は **SlideApp** とする。

## 1. 目的

Marp形式のMarkdown（.md）を、スライドのプレビュー上で直接編集できる軽量なWindowsデスクトップアプリ。
AIコーディングエージェントが作ったスライドを、人が見た目を確認しながら細かく直す用途を想定する。
UIはPowerPointの「標準」表示（左にスライド一覧、中央に大きなスライド）を手本にする。

### 想定ワークフロー

1. AIエディタでMarpスライド（.md）を作成する
2. 本アプリで同じローカルファイルを開く
3. スライド上の文字をクリックし、その場で編集する
4. 編集内容を元のMarkdownファイルへ保存する
5. AIエディタで追加修正する
6. 本アプリが外部変更を検知して表示を更新する
7. 必要に応じて2〜6を繰り返す

### 最重要原則

| 原則 | 本アプリでの意味 |
|---|---|
| ローカルファースト | ネットワーク不要。データはローカルの.mdだけ |
| 軽量・高速 | 起動・描画・編集の応答を速く保つ。常駐しても重くならない |
| Marp互換 | Marp Coreで描画し、Marpの記法を独自形式に変えない |
| Git共存 | 差分が最小になる保存。.gitに触れない。自動commitしない |
| 元構造の保持 | 編集した文字の範囲だけを書き換え、他の行は1バイトも変えない |
| 双方向同期 | 外部エディタの変更を取り込み、自分の保存で無限更新しない |

## 2. 環境と制約

- 対象OS：Windows 11（x64）
- ローカルアプリとして動作し、VS Codeなどの外部エディタに依存しない
- ユーザーがサーバーを起動する操作は不要
- Electronは使わない（→ Tauri 2を採用。[design.md](design.md)）
- ユーザー登録・ログイン・データベースは不要
- Gitリポジトリを独自形式へ変換しない
- Marpの既存記法を独自形式に置き換えない
- 配布・更新はGitHub Releases。アプリ上から手軽に更新できること

## 3. 必須機能（P0）

### F-01 ローカルファイル操作

- ファイル選択ダイアログから.mdを開ける
- 既存ファイルを直接編集・上書き保存できる
- Ctrl+Sで保存できる
- 開いているファイルのパスを表示する
- 未保存状態を見て分かるように表示する
- 最近開いたファイルを記憶する（最大10件）

保存時に維持すること：

- UTF-8エンコーディング（BOMの有無も維持）
- 元ファイルの改行コード（CRLF / LF / 混在のいずれも行単位で維持）
- 既存のMarkdown記法
- ファイル内の未編集部分（バイト単位で不変）

### F-02 Marpスライド表示

- Marp Coreでスライドを描画する
- ページ区切り（`---`）、`headingDivider` などMarpの区切り方に対応する
- Marp組み込みテーマ（default / gaia / uncover）とカスタムテーマを反映する
- `<style>` や `style` ディレクティブのカスタムCSSを反映する
- 背景画像（`![bg]`）・ローカル画像を表示する
- 相対パスを、開いた.mdの場所から解決する
- スライド間を移動できる
- ページ番号（現在 / 全体）を表示する
- ウィンドウサイズに合わせて拡大縮小する

表示はMarp CLIやVS Code拡張の結果にできるだけ一致させる。

### F-03 スライド上での直接文字編集（最重要）

- スライド上の文字をクリックすると編集を始め、その位置にカーソルを出す
- キーボードで文字を追加・削除・置換できる（日本語IMEを含む）
- 編集結果を即座に画面へ反映する
- 編集中もスライド全体のレイアウトを維持する
- 編集した文字列を元Markdownへ反映する
- Shift+Enterで同じ段落・リスト項目内に改行する。引用・リストの継続に必要な接頭辞を維持する
- Enterで本文の段落、または同じ階層・記号形式のリスト項目をカーソル位置で分割する。番号付きは次の番号を挿入し、後続項目のソースは変えない
- 改行後は新しい行の先頭にカーソルを置き、Ctrl+Z一回で改行前へ戻せる
- 項目・段落・行の末尾でも改行後に入力を続けられる。未入力で終了した空のリスト項目は残し、空の段落・行は改行の挿入を履歴に残さず取り消す
- IME確定用のEnterは改行にしない。確定後の削除・保存が合成状態の取り残しで止まらない
- 見出し・表・装飾の途中など、安全な分割を検証できない場所では改行を拒否して理由を表示する

初期の対象：スライドタイトル、見出し、通常の本文、箇条書き、太字・斜体・取り消し線・リンク内の文字。

- 文字の変更でMarkdownの装飾記法を壊さない
- 安全に直接編集できない要素は編集を無効にし、理由を表示する
- 壊れる可能性がある編集を推測で実行しない

### F-04 Markdownへの逆反映

1. Markdownを解析する
2. 表示要素と元ソースの位置を対応付ける
3. ユーザーが表示要素を編集する
4. 対応するソース範囲だけを変更する
5. Marp Coreで再描画する

- Markdown全体をHTMLから再生成しない
- 対象外の記述、見出し記号、強調記号、Marpディレクティブ、コメント、front matterを変えない
- 同じ文字列が複数あっても、編集した箇所だけを変更する
- 文字列検索による一括置換は禁止

### F-05 外部ファイル変更の自動検知

- 開いているファイルを監視し、外部変更で再読み込み・再描画する
- 表示中のページをできるだけ維持する
- 内容が変わっていなければ再描画しない。変わったスライドだけ差し替える

競合対策：

- 未保存の編集がなければ自動で更新する
- 未保存の編集があれば自動で上書きせず、選択肢を出す
- 保存直前にディスク上の内容を再確認する
- 自分の保存による変更通知では再読み込みしない

### F-06 Gitとの共存

- Git管理中の.mdを直接編集できる
- .gitフォルダに触れない。自動commit・pushをしない
- ファイルの保存場所を変えない
- 差分が読みやすい状態を保つ（編集した行以外を変えない）

Git操作機能は実装しない。

### F-07 アプリの更新

- GitHub Releasesで配布する（NSISインストーラー、ユーザー単位インストールで管理者権限不要）
- 起動時に新しい版を確認し、あればお知らせする（設定で無効化可）
- メニューの「更新を確認」から、ダウンロード・インストール・再起動までアプリ内で完結する
- 更新パッケージは署名して検証する

### F-08 編集可能なPowerPoint（.pptx）へのエクスポート

開いているMarpスライドを、PowerPointで編集できる.pptxに書き出す。
Marp CLIの `--pptx`（全面画像）とは異なり、文字はテキストボックスとして編集できること。

- メニューの「PowerPointにエクスポート」から保存先を選んで書き出す（既定は同じフォルダの `<名前>.pptx`）
- 外部ツール（Marp CLI、LibreOffice、PowerPoint本体）を必要としない
- スライドサイズはMarpの `size`（16:9 / 4:3 / 任意のwidth・height）に合わせる
- 見た目はアプリ上の表示とできるだけ一致させる

要素ごとの書き出し方：

| Marpの要素 | PowerPointでの形 |
|---|---|
| 見出し・本文・箇条書き | テキストボックス（編集可）。フォント、サイズ、色、太字・斜体・下線・取り消し線、リンク、行間、箇条書き記号と階層、配置を反映 |
| 表 | PowerPointの表（編集可）。セルの文字・色・罫線を反映 |
| 画像（インライン） | 画像。位置と大きさを反映 |
| 背景色・背景画像（`bg`、`bg left` などの分割含む） | スライド背景または最背面の画像 |
| ヘッダー・フッター・ページ番号 | テキストボックス（編集可） |
| 発表者ノート（Marpのコメント） | スライドのノート |
| コードブロック | テキストボックス（等幅フォント、色付き）。再現できない場合は画像 |
| 数式・絵文字・SVG・複雑なCSS装飾（グラデーション文字、影、変形など） | 画像として貼る（見た目を優先） |

精度の考え方：

- 位置と大きさは、アプリ上で描画したスライドの実測値から決める（推測しない）
- 文字の折り返しはPowerPointとブラウザで差が出るため、テキストボックスは自動調整をオフにし、余白を少し持たせる
- 編集可能にできない要素は画像にして、見た目の崩れを避ける
- 書き出し後に、画像にした要素の数と理由を一覧で表示する
- スライドの日本語はプレビュー・PowerPointともに常に Noto Sans JP とする（CSSの和文指定より優先）。英数字はスライドCSSの指定を維持する。アプリUIのフォントは変更しない。PowerPointの日本語範囲の文字ランは、東アジア用フォントを Noto Sans JP とし、欧文指定とは分ける。範囲外の注音字母・ハングルなどは元の指定を維持する。OSにないWebフォントは近い代替フォント名で書き出し、その旨を表示する

## 4. UI・操作

### 4.1 レイアウト

- スライドを大きく表示する
- 左のサイドバーにスライド一覧（サムネイル）を置き、折りたためる
- 保存状態を常に確認できる

### 4.2 操作

| 操作 | 動作 |
|---|---|
| クリック | 文字の編集を開始 |
| Enter / Shift+Enter | 段落・項目の分割 / 同じ段落・項目内の改行（IME変換中を除く） |
| 矢印キー | 編集中：カーソル移動 / 非編集時：スライド移動 |
| PageUp / PageDown、Home / End | 非編集時：前後・最初・最後のスライドへ移動 |
| Ctrl+S | 保存 |
| Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） | 元に戻す / やり直す |
| Esc | 編集を終了してフォーカスを外す |
| Ctrl+O | ファイルを開く |
| Ctrl+E | PowerPointにエクスポート |

### 4.3 デザイン

- シンプルで無駄のないUI。スライド表示領域を最大限確保する
- ダークモード対応（OS設定に追従、手動切替も可）
- 余計なアニメーションを避ける
- 起動しっぱなしでも快適（アイドル時のCPU使用率ほぼ0）

## 5. 非機能要件（目標値）

| 項目 | 目標 |
|---|---|
| インストーラーサイズ | 15MB以下 |
| 起動からスライド表示 | 1.5秒以内（50枚程度） |
| 入力から画面反映 | 1フレーム以内（ブラウザの編集をそのまま表示） |
| 外部変更の反映 | 検知から500ms以内 |
| アイドル時メモリ | 200MB以下（WebView2込み） |

## 6. 対象外（P0ではやらない）

- スライドの追加・削除・並べ替え
- 表・コードブロック・数式・画像の編集、書式の付け外し
- 複数ファイル同時編集（タブ）
- Git操作、PDF・画像へのエクスポート
- PowerPointからMarpへの取り込み（逆変換）
- PowerPointのアニメーション・画面切り替え効果
- macOS / Linux 対応
