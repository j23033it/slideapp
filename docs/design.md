# 設計

要件は [requirements.md](requirements.md) を参照。

## 1. 技術選定

| 項目 | 採用 | 理由 |
|---|---|---|
| デスクトップ基盤 | **Tauri 2**（Rust + WebView2） | Electronを使わずにWebの描画力を得る。WebView2はWindows 11に標準搭載で、インストーラーが小さい |
| 描画 | **@marp-team/marp-core**（フロントエンドで実行） | Marp公式の描画エンジン。CLI・VS Code拡張と同じ結果になる |
| Markdown解析 | Marp Core内蔵のmarkdown-it（プラグインで位置情報を追加） | 描画と解析で同じパーサーを使い、対応関係のずれを防ぐ |
| UI | **Preact + TypeScript + Vite** | 軽い（約4KB）。スライド本体のDOMはPreactに管理させず、編集エンジンが直接操作する |
| PPTX生成 | **PptxGenJS** | ブラウザで動き、テキスト・表・画像・ノート・任意サイズに対応 |
| ファイル監視 | Rust `notify` クレート | OSの変更通知を使い、ポーリングしない |
| 更新 | `tauri-plugin-updater` + GitHub Releases | 署名付き更新をアプリ内で完結できる |
| テスト | Vitest（編集エンジン・書き出し変換）、`cargo test`（ファイル入出力） | 最重要の対応付けをテストで固める |

### 依存の脆弱性対応

`@xmldom/xmldom` は脆弱性の影響経路に到達しないものの修正版 `0.9.12` に固定し、KaTeX は条件付きで影響を受ける可能性があるものの互換性のため `0.17` のままとする。

パッケージ管理はnpm。CSSは素のCSS + CSS変数（ライト・ダークのトークン）。

## 4. ドキュメントモデル（`src/document`）

### 4.1 読み込みと保存の不変条件

**編集していない部分は、保存後もバイト単位で同一であること。** これを次の方法で保証する。

- Rustはファイルをバイト列で読み、UTF-8として妥当か確認してから返す。BOMは取り除いて `hasBom` として別に返す。UTF-8でない場合は開かずにエラーを表示する（勝手に変換しない）
- フロントエンドは本文を **LF正規化した文字列** `text` と、**行ごとの改行コード配列** `eols: ("\r\n" | "\n" | "")[]` に分けて持つ
  - markdown-itは内部で `\r\n` を `\n` に変換するため、正規化した文字列を渡すと位置がそのまま一致する
  - 保存時は `text` を行に分け、各行に元の改行コードを付け直す。CRLF・LF・混在のどれでも元に戻る
  - 編集で行が増えた場合、新しい行にはファイル内で多い方の改行コードを使う（同数ならLF）。既存の各改行コードとBOMの有無は維持する
- 末尾に改行がないファイルは、最後の行の改行を `""` として保持する
- `\0` はmarkdown-itが置き換えるため、含むファイルは編集を無効にして閲覧のみとする

### 4.2 編集の単位

すべての変更は `{ start, end, insert }`（正規化文字列上の範囲置換）で表す。
履歴（元に戻す・やり直す）もこの単位で持つ。全文の書き直しは行わない。

- 連続した文字入力は、同じ文字ラン内で1秒以内なら1つの履歴にまとめる
- 改行は前後の文字入力とまとめず、一つの範囲置換を一回の履歴にする
- 履歴にはカーソル位置（どのランの何文字目か）も記録し、元に戻したときに復元する
- 外部変更による再読み込みは履歴を消去する（別の版の上に古い履歴を当てると壊れるため）

### 4.3 保存状態

| 状態 | 意味 | 表示 |
|---|---|---|
| clean | ディスクと一致 | ステータスバーに「保存済み」 |
| dirty | 未保存の変更あり | タイトルに `●`、ステータスバーに「未保存」 |
| conflict | 未保存の変更があり、ディスクも外部で変わった | 黄色の帯で選択肢を表示 |
| readonly | UTF-8でない、`\0` を含むなど | 帯で理由を表示 |

`diskHash`（最後に読んだか保存した時点のディスク内容のSHA-256）を持ち、競合判定に使う。

## 5. Rust側（`src-tauri`）

### 5.1 コマンド

| コマンド | 内容 |
|---|---|
| `open_file(path)` | バイト列を読み、`{ text, hasBom, hash, mtime }` を返す。監視を開始し、資産プロトコルの許可範囲に親フォルダを加える |
| `save_file(path, text, hasBom, expectedHash)` | ディスクの現在のハッシュが `expectedHash` と違えば保存せず `Conflict` を返す。同じなら原子的に保存し、新しいハッシュを返す |
| `read_theme_config(markdownPath)` | .mdのフォルダから上へ（`.git` のあるフォルダかドライブ直下まで）`.marprc.yml` / `.marprc.yaml` / `.marprc.json` / `.vscode/settings.json` を探し、最初に見つかった設定のテーマCSSを `{ themes: [{ path, css }], warnings }` で返す。JS設定・URLテーマは読まず警告にする（JS設定は実行せず、本文に `themeSet` を含むときだけ警告する。`engine` などテーマに関係しない設定では警告しない） |
| `recent_files_get / recent_files_add` | 最近使ったファイル（最大10件）。アプリ設定フォルダのJSONに保存 |
| `settings_get / settings_set` | テーマ（system/light/dark）、更新確認の有無、サイドバー幅、openTabs（タブのパスの並び）とactiveTab（アクティブなパス）など |
| `stop_watching(path?)` | 指定パスの監視を停止する。省略時は全対象を停止する |
| `write_binary(path, bytes)` | PPTXの書き出し |
| `import_image(md_path, source_path)` | 外部画像を `<.mdのフォルダ>/images/`（フォルダがなければ作成）へ一時ファイル経由で安全にコピーし、相対パスを返す。同じ名前の既存ファイルがあれば内容を比較し、同一ならそれを使い、異なれば `name-2.png` のように連番を付与して上書きを防ぐ。ファイル名の空白・Markdown特殊文字（`( ) < > [ ] # % ? \`、制御文字）は `-` に置換する。選択画像がすでに `.md` のフォルダ以下にある場合はコピーせずその相対パスを返す |

### 5.2 原子的保存

1. 同じフォルダに元の名前と無関係な短い一意名 `.slideapp-<ランダム8文字>.tmp` を `create_new` で確保して書き込み、`flush` と `sync_all` を行う。バックアップも同じ方式で `.slideapp-<ランダム8文字>.bak` を確保する
2. 保存開始時と一時ファイルの書き込み後に、元ファイルのハッシュを `expectedHash` と照合する。既存ファイルは Windows の `ReplaceFileW` で置換し、元ファイルの属性・ACLを引き継ぐ。保存先が無い場合は上書きしない移動（`MoveFileExW`、フラグ無し）を使い、移動までに宛先が現れた場合は `conflict` を返す
3. 置換成功後もバックアップのハッシュを `expectedHash` と照合してから削除する。不一致なら最終確認後の外部変更として `conflict` を返す。バックアップを使って外部内容を元のパスへ戻し、その際のディスク内容も別のバックアップに退避する。退避内容が自分の保存内容と一致するときだけ削除し、新たな外部内容や照合不能な内容はパスをログに出して残す。復旧に失敗した場合も外部内容のバックアップは削除せずパスをログに出す。自分の編集内容はフロントエンドのメモリに残る
4. `ReplaceFileW` がエラー1177で失敗した場合は、バックアップへ移った元ファイルを上書きしない移動で戻す。宛先が現れた場合はその内容を維持して `conflict` を返す。ほかの復旧失敗は元ファイルのバックアップを残し、そのパスをエラーとログに出す
5. 操作が作成した一時ファイル・不要なバックアップは削除を短い間隔で再試行し、それでも残る場合はパスをログに出す。次回の操作は別の一意名を使うため、残ったファイルで保存が妨げられない

一時ファイルは通常は保存中だけ存在する。復旧不能なバックアップや削除できなかったファイルは上記のとおり残す。
`.gitignore` の追加は利用者のリポジトリを変えるため行わない。

### 5.3 ファイル監視と自己保存の判別

- `FileService` は絶対パスごとに監視セッションを持つ。開く操作は他の監視を止めず、`stop_watching(path)` はそのパスだけ、パス省略時は終了処理として全監視を止める。同じ対象の再読み込みでも監視を作り直さない。
- 各セッションの既知ハッシュ・削除状態・デバウンス・再試行・自己保存のロックを独立させ、通知には対象パスを含める。原子的保存の手順は5.2を維持する。
- `notify` で開いているファイルの**親フォルダ**を非再帰で監視する（置き換え保存をするエディタではファイル単体の監視が外れるため）。対象ファイル名のイベントだけを使う
- イベントは150msまとめてから（デバウンス）ファイルを読み、ハッシュを計算する
- 共有違反などで読み取りに失敗した場合は、35msから最大2秒まで間隔を倍増し、読み取れるか監視が停止・切替されるまで再試行する。待機中は監視停止と新たなイベントを受信でき、保存用のロックも保持しない。短い共有違反は通知せず、読み取り失敗が続く場合に1回だけ通知する
- ハッシュが `diskHash` と同じなら何もしない。自分の保存直後の通知はこれで無視され、無限更新にならない
- 違えばフロントエンドへ `file-changed { text, hasBom, hash }` を送る
- ファイルが消えた・名前が変わった場合は `file-removed` を送り、帯で知らせる（内容はメモリに残し、「別名で保存」を促す）。削除直後の再出現も同じ再試行で確認する

## 6. 描画（`src/marp`）

### 6.1 Marp Coreの設定

- `new Marp({ script: false, html: カスタム許可リスト, math: 'mathjax' })`。描画結果に `<script>` を含めず、自動縮小などのブラウザ用処理は `@marp-team/marp-core/browser` を Shadow Root に対して呼ぶ
- HTMLはMarp Core既定の許可リストに加え、7.13 のテキストボックス用 `<div data-box>` だけをカスタム許可リストで通す。属性は `data-box` と `style` のみとし、`style` は決められた書式（`position:absolute`、整数pxの座標・幅、省略可能な整数ptの文字サイズ）に完全一致するか検査関数で検証する。`html: true` は使わず、プレビュー・サムネイル・PowerPoint書き出し（`svgHtmlAllowlist`）で同一の許可リストを共有する。任意のHTMLやスクリプトは実行しない（ローカルファイル経由の危険な動作を防ぐ）
- CSPで、外部スクリプトとインラインスクリプトを禁止する。画像は `asset:`、`https:`、`data:` を許可する

### 6.2 テーマ

- 組み込み（default / gaia / uncover）はそのまま使う
- カスタムテーマは `read_theme_config` で得たCSSを `marp.themeSet.add()` で登録する
- `<style>` と `style` ディレクティブはMarp Coreが処理する

### スライドの日本語フォント（issue #21）

- プレビュー・サムネイル・書き出し用DOMの日本語は、スライドCSSの指定にかかわらず、Windowsの **Noto Sans JP** を使う。英数字など対象範囲外は元のCSSのフォントリスト・ウェイト・スタイルを維持する。アプリUI（`src/styles`）のフォントは変更しない。
- 日本語専用の一意な別名を `document.head` の `@font-face` に登録し、スライドCSSの指定元ルール（疑似要素・条件付きルールを含む）の `font-family` の先頭に追加する。指定の詳細度・優先度と継承を保ち、継承する子要素や編集用spanへ計算済みフォントを固定しない。既存のインライン指定・SVGのフォント属性がある場合はその指定だけを補正し、編集用DOMへ属性やstyleを追加しない。`unicode-range` 以外の文字は元のリストへ進む。同名の著者フォント面でシステムフォントを隠さない。Shadow DOM内の `@font-face` に依存しない。再描画時は新しいCSSルールに適用し、同じ別名を重複追加しない。著者CSSの `!important` も指定元で補正する。Markdownと文字ノードは変更せず、HTML許可リストも維持する。
- 対象は U+2E80–2FFF（CJK部首・記述記号）、U+3000–30FF（CJK記号・句読点、ひらがな、カタカナ）、U+3190–319F（漢文訓点）、U+31F0–31FF（仮名拡張）、U+3200–33FF（囲みCJK・互換単位）、U+3400–4DBF / 4E00–9FFF / F900–FAFF（漢字）、U+FE10–FE1F / FE30–FE4F（縦書き・CJK互換記号）、U+FF01–FF60 / FFE0–FFE6（全角英数字・記号）、U+FF61–FF9F（半角仮名・句読点）、U+1AFF0–1AFFF / 1B000–1B16F（追加の仮名）、U+20000–3347F（補助漢字・互換漢字）。ASCII・欧文句読点・注音字母・ハングル・絵文字は対象外。範囲は [Unicode 17 Blocks.txt](https://www.unicode.org/Public/17.0.0/ucd/Blocks.txt) の日本語で使うブロックに基づく。Noto Sans JP自体にない字形はブラウザ・Officeのフォールバックとなる。
- 合成フォントと `local()` にフェイス名を使う根拠は [CSS Fonts 3](https://www.w3.org/TR/css-fonts-3/#composite-fonts) を参照。Noto Sans JPがない環境ではプレビューは元のCSSへフォールバックし、書き出しは欠落を明示して停止する（別の和文フォントで黙って計測しない）。
- 既知の制約（実際のスライドではまず使われない書き方のため対応しない）：`font` 一括指定に `var()` を含む場合（例：`font: var(--body)`）は日本語の置き換えが効かない。`var(--x, initial)` のように変数展開後にCSS共通キーワードになる `font-family` では、欧文フォントが変わることがある。インストールされていないフォントを先頭に書いた要素に `::first-line` で別のフォントを指定すると、書き出しの欧文フォントがプレビューと異なることがある。太字・斜体の異体字セレクタ（IVS）は、基底の漢字と別のランに分かれ、字形が変わることがある。

### 6.3 相対パスの解決

- markdown-itのコア規則を `inline` の直後に追加し、`image` トークンの `src` が相対パスなら、開いたファイルのフォルダを基準に絶対パスにしてTauriの資産URL（`convertFileSrc`）に置き換える。背景画像（`![bg]`）も画像トークンから作られるため、同じ処理で対応できる
- テーマCSSや `<style>` 内の `url(...)` の相対パスも、描画後のCSSを書き換えて同様に解決する
- Markdownソースは変更しない（描画時だけの変換）

### 6.4 再描画の抑制

- 描画結果をスライド単位のHTML文字列で保持し、前回と違うスライドだけDOMを差し替える（サムネイルも同じ）
- 外部変更で全体の内容が同じなら描画しない
- 再読み込み後は同じスライド番号を表示する（枚数が減った場合は最後のスライド）

## 7. 直接編集エンジン（`src/editing`）— 最重要

### 7.1 基本方針

1. **位置は解析時に記録し、推測しない。** markdown-itの解析中に、各文字トークンが元ソースのどこから来たかを記録する
2. **変更後は再解析して確かめる。** 書き換えたソースをもう一度解析し、構造が変わっていないこと・意図した文字になったことを確認してから採用する
3. **確かめられないものは編集させない。** 対応が取れない、または曖昧な要素は読み取り専用にし、理由を表示する

### 7.2 対応表の作り方

**ブロック**：`heading` / `paragraph` の `inline` トークンは `map`（行範囲）を持つ。
`inline.content` の各行が、元の各行のどこに当たるかを次の規則で決める。

- 行頭側で取り除かれてよいのは、空白・`>`・リスト記号（`-` `+` `*` `1.` `1)`）・見出し記号 `#` だけ
- 行末側で取り除かれてよいのは、空白と見出しの閉じ記号（` ##`）だけ
- 当てはまる位置がちょうど1つなら採用する。0個または2個以上なら、そのブロックは読み取り専用にする
- Setext見出し（下線 `===` / `---`）は下線の行を除いて照合する

**インライン**：markdown-itのインライン解析器に位置追跡を入れる。

- 各インライン規則の前後で `state.pos` を記録し、規則が作ったトークンに `[開始, 終了)` を付ける
- 普通の文字は `state.pending` にためられてから `pushPending` でトークンになるため、`pushPending` を包んで、ため始めた位置と終わった位置を付ける
- markdown-itの `fragments_join` と `text_join` は隣り合う文字トークンを連結し、位置情報が失われる。そこで、それぞれの直前に同じ連結を行う独自規則を入れ、連結した部分ごとの位置（セグメント）を保持する
- 各セグメントは「そのまま」（表示文字とソースが1対1）か「特殊」（`\*` や `&amp;` のように、ソースと表示が異なり分割できない）のどちらか
- Marp Coreの後処理（絵文字の置き換えなど）で分割され、位置情報がなくなったトークンは読み取り専用にする

この位置追跡はmarkdown-itの内部構造に依存するため、`markdown-it` と `@marp-team/marp-core` の版は固定し、更新時は対応表のテストをすべて通すことを条件にする。

### 7.3 描画への印付け

- 文字トークンの描画規則を包み、出力を `<span data-sm-run="ランID">` で囲む。それ以外のHTMLは変えない
- 包んだ規則の出力が、トークンの文字をHTMLエスケープしたものと異なる場合（絵文字の画像化など）は、そのランを読み取り専用にする
- 編集できるブロック要素（`h1`〜`h6`、`p`、`li` 内の `p` または `li` 本体）に `data-sm-block="ブロックID"` を付ける
- 描画後にDOMを確認し、`span` の `textContent` がランの文字と一致しなければ読み取り専用にする

### 7.4 編集の流れ

Shadow DOM内の選択範囲は編集面のShadow Rootの `getSelection()` から取得する。WebView2はスクリプトで置いた直後の選択をDocumentから取得できても、マウスドラッグ・矢印移動・文字入力後にはホスト要素へ丸めて返すため、Document側のノード・オフセットや `isCollapsed` では入力位置を判断しない。Shadow RootのAPIがないテスト環境だけDocumentへフォールバックする。

スライド本文は編集開始前も `user-select: text` にして、アプリ外枠の選択禁止を引き継がせない。選択・コピーだけでは編集を開始しない。

1. クリックした位置に編集できるランがあれば、そのブロック要素を `contenteditable` にし、クリック位置にカーソルを置く。編集できないものを押したら、理由をステータスバーに表示する（例：「表は直接編集に未対応です」）。ドラッグ・ダブルクリックで作った選択範囲の直後に届くclick（選択が編集面の中にあり、押す前から範囲が変わったか複数回クリックの場合）は選択の終わりとみなし、カーソルを動かさず編集も開始しない。選択しただけではソースを変更しない
2. ブロック内の読み取り専用部分（インラインコード、画像、HTML、数式）には `contenteditable="false"` を付け、カーソルが入らないようにする
3. 入力は次の2段階で扱う
   - **入力前（`beforeinput`）**：複数のランにまたがる選択範囲への入力、ブラウザ標準の元に戻す、太字以外の書式変更（Ctrl+Iなど）は止めて、理由を表示する（太字の付け外し Ctrl+B は 7.15 で処理する）。改行はブラウザのDOM変更を止め、下記の範囲置換で処理する。ランの先頭でBackspaceを押した場合などは、隣のランへの操作としてアプリが処理する
   - **入力後（`input`、IME変換中は `compositionend` 後）**：対象ランのテキストノードを読み、元の文字との差分（共通の前後を除いた部分）を求める
4. 差分をソースの範囲置換に変換する。差分が「特殊」セグメントの途中にかかる場合は、そのセグメント全体を置き換える
5. 置換後のソースを再解析して**検証**する（7.5）。通らなければ、入力した記号に `\` を付けて再度検証する。それでも通らなければ、DOMを元の文字に戻して理由を表示する
6. 採用したらモデルを更新し（未保存状態にする）、対応表を作り直す。画面のDOMはブラウザが編集したものをそのまま使うため、入力のたびに再描画はしない
7. 編集の終了時（Esc、ほかの場所のクリック、スライドの切り替え）にMarp Coreで再描画し、サムネイルも更新する

貼り付けは書式なしの文字だけを受け付け、改行は空白に変える。

IMEの合成状態は `compositionstart` / `compositionend` を正とする。終了後に遅れて届く `input` / `beforeinput` の `isComposing` で合成を再開しない。開始イベントが欠けた入力では、その入力イベントのコミットを保留するが、保存用ゲートの合成状態は立てない。`isComposing=false` かつ `keyCode!==229` のkeydown、blur、クリックによる編集先の変更、明示的な編集終了では残ったDOMの文字を検証・コミットしてから合成待ちの操作を解放する。IME確定用Enterは改行として処理しない。

変換中は編集中ブロックの属性、スナップショット、描画を変更しない。子ブロックへ入力先が移る場合は合成前に記録したスナップショットを使う。終了時のコミット後、保存待ちの解放だけを `setTimeout(0)` で次タスクへ送る。タイマー実行前に届く最終 `input` を保存に含めるため、タイマーで残ったDOMを再検証・コミットしてから待ちを解放する。待機中のCtrl+Sやblurでは早期解放しない。最終inputがなくてもタイマーで解放する。新しい明示的な `compositionstart` ではタイマーを取り消し、次の終了まで予約を持ち越す。disposeでもタイマーを取り消す。TSFによる確定Enterの再送には識別情報がないため、`compositionend` 後100ms以内の通常Enterと改行beforeinputも抑止する（クリック・新しい合成開始で解除）。この時間内の意図的なEnterも抑止される制約がある。

保証範囲は保存待ちの解放までとする。待機（次タスク）中にクリック・Escape・別ランへの入力・Undoなどが割り込んだ場合、および待機後に届くinputは保証しない。いずれも変更前からある経路で、実機WebView2の記録では最終inputはcompositionendより前に届く。操作を保留して再実行する仕組みは追加しない。

開始イベントが欠けた仮入力状態もアダプタから参照し、その直後の通常Enterは文字の確定として扱う。100msのEnter再送抑止はcompositionendだけでなく、通常keydown・blur・編集終了などの代替確定にも共通で設定する。通常の入力だけでは抑止時間を延長しない。

#### 改行・段落分割

- 解析時に記録した行の対応、リスト項目の範囲・階層・記号、引用の接頭辞、インライン装飾の位置から挿入位置と継続接頭辞を決める。文字列検索で編集位置を探さない
- Shift+EnterはソースにLFと継続接頭辞（リストの内容字下げ、引用の `> `）を挿入する。再解析で同じブロック・同じ項目内に改行が一つ増えたことを照合する
- Enterは通常段落なら空行（引用内は引用の空行）を挿入する。リスト項目の最初の段落なら同じ階層・記号で新しい項目を挿入する。番号付きは元の番号+1と元の区切り記号（`.` / `)`）を使い、後続の番号は変えない
- 再解析で対象のブロックだけが期待どおり分かれ、対象外のブロック・インライン構造・表示文字・スライド構造が変わらないことを検証する。子リストや複数段落を含む項目の分割など対応が曖昧な場合は拒否する
- 見出し・表、装飾の途中、文字とソースの対応が一意でない位置は拒否する。理由は改行を安全に追加できない旨として表示する
- 採用したら一つの範囲置換として履歴に記録し、再描画する。新しい行の最初の編集可能ランへカーソルを移す

#### 末尾の空の編集先

- 項目・段落・行の末尾では、記録済みの挿入点を `[位置, 位置)` として持つ空の文字ランを作る。空のランにも通常と同じIDとブロック対応を付け、ソースに不可視文字やHTMLは入れない。最初の文字入力はこのゼロ長範囲への挿入として再解析・検証する
- 空の項目は `- ` / `8. ` など内容開始位置までの接頭辞を保持して永続化する。未入力で終了しても空の `li` を残す。解析し直した場合も、トークンが空の項目であり、行の接頭辞と挿入位置が一意なら空のランを復元する
- Markdownが空の段落・末尾のsoftbreakをトークンとして保持しない場合は、描画専用の仮文字を記録済み挿入点に入れて解析する。その仮文字のランをゼロ長ランに戻して描画し、他のソース座標のずれも戻す。仮文字はドキュメントモデル・保存・履歴には渡さない。空ランの表示はキャレット用の最小寸法を持たせる
- 空の段落・行を作る範囲置換は仮編集としてモデルに反映し、まだ履歴へ入れない。最初の検証済み文字入力で改行と文字を一回の履歴として確定する。入力せずEsc、クリック、フォーカス移動、保存前の編集終了、空行の先頭でのBackspaceを行ったら、記録した挿入範囲だけを取り消し、元の改行コード配列と履歴・Redoを復元する。Ctrl+Zも仮編集だけを取り消す
- 空ランへのカーソルは、ラン自身のオフセット0へ置く。Shadow Rootから得た選択が空ラン自身を指していれば、空行にいるとみなす。同じ空行ブロック内でのフォーカス移動でも取り消さない
- selectionchangeで空ランの外へ選択位置が移った場合も仮編集を取り消す。移動先は記録したソース位置から取消後のランへ対応付け、UTF-16オフセットと選択方向を復元して編集を続ける。選択通知が遅れる場合は通常keydown・beforeinputでも照合する。beforeinput中にDOMを再描画した場合、古いDOMへの標準入力は止め、文字入力は新しい選択範囲に対して既存アダプタで処理する。変換中はこの取消によるDOM変更を行わない
- 仮編集の開始・確定・取消は範囲置換の付帯情報としてDocumentModelへ渡す。App側の通常のコミット・再描画・履歴経路を共用し、全文差し替えや履歴の相殺エントリは作らない
- 空の編集先を確定させる最初の文字入力では、仮文字で検証した構造と実際の文字の構造が一致した場合だけ通常ランへ移す。通常入力と同じDOMを維持し、空ラン用の表示属性だけを外す。IME入力ではcompositionendまでDOMを維持する
- 先頭での分割は引き続き安全に対応できる場合だけとし、今回の空ランは末尾の挿入に限定する

#### Tabによる階層変更

- 編集中のTab / Shift+Tabはフォーカス移動を止め、残った文字をEnterと同じ経路でコミットしてから、項目と子孫を一段深く／浅くする。Ctrl・Meta・Alt付き、または既に既定動作を抑止されたTabは処理しない。IME変換中は階層を変更しない。項目以外、先頭項目の字下げ、最上位項目の字下げ解除は理由を表示して拒否する
- 解析時に項目の行範囲、親・兄弟、記号と内容の開始桁を記録する。深くするときは直前の兄弟の内容開始桁まで、浅くするときは親の記号の桁まで、対象部分木の各非空行の行頭だけを範囲置換する。空行、記号、後続の番号は保持する。新しい番号付き子リストの先頭になる場合だけ番号を1にできる（区切り記号は保持）
- 字下げのタブ、引用などのコンテナ、遅延継続行、範囲や桁が曖昧な項目は拒否する。再解析で対象部分木だけの階層が±1変わり、全項目の表示文字、対象外の階層、ほかのブロックとスライド構造が保たれることを検証する。浅くした後ろの兄弟はソースの字下げを保ち、新しい項目の子になることを許す
- 複数の範囲置換は元の解析座標で記録し、後ろから適用してDocumentModelの一つの独立した履歴にまとめる。各行の改行コードとBOMを保持し、再描画後は同じ文字ランの同じUTF-16位置へキャレットを戻す。Appの既存のonCrossRun経路を使う

#### 表のセルの文字

GFMの表は、セルの中の文字だけを編集できる。行・列の追加や削除、並べ替え、配置（`:---:`）の変更は扱わない。

- 対象は、最上位（リスト・引用などのコンテナの外、字下げなし）にある表の `th` / `td` の `inline` トークンだけとする。それ以外の表は従来どおり読み取り専用にする
- セルの位置は、その行のソースを markdown-it 14.3.3 の `escapedSplit` と同じ規則（先頭・末尾の `|`、`\|` のエスケープ）で区切り、列番号で決める。文字列検索では探さない。区切ったセルの前後の空白を除いた範囲が `inline.content` とバイト単位で一致する場合だけ採用し、各ランの位置はこの範囲を基準に記録する
- 次のセルは読み取り専用にし、理由を表示する：`\|` を含むセル（表の分割で `\` が取り除かれ、ソースと内容が一致しないため）、見出し行より列が少ない行で補われたセル（ソースがない）、区切りや一致を確定できないセル
- セルの `th` / `td` に `data-sm-block` を付け、セル単位で `contenteditable` にする。ほかのセル・表の外へはカーソルを移さない
- セル内で `|` を入力した場合は、列の分割を変えるため拒否し、理由を表示する。改行（Enter / Shift+Enter）とTab / Shift+Tabも、表の中では拒否して理由を表示する
- 検証は7.5と同じ条件に加え、表の行数・列数・各列の配置、すべてのセルの表示文字（編集したセル以外）が変わらないことを確かめる。ブロック構造の比較に含まれるため、別のセルへのはみ出しや表の崩れは拒否される

削除は次の3つに対応する。いずれも記録済みの範囲だけを置き換え、再解析で検証する。

- **ランの一部の削除**：通常の文字編集と同じ
- **ランをすべて消す**：セル内の文字ランを空にした結果、そのテキストトークンだけがなくなり、ほかのインライン構造（強調、`<br>` など）と表示文字が保たれる場合に採用する。そのランがセルの唯一の内容なら、セルは空（`|  |` の空白は保持）になる。空のセルには、セル内容の開始位置にゼロ長の文字ランを作り、再び入力できるようにする（解析し直したときも、ソースが空白だけのセルなら同じ位置に復元する）。削除後は再描画し、空のセルならそのゼロ長ラン、それ以外なら同じセル内の直前のランの末尾（なければ直後のランの先頭）へカーソルを置く。強調などの中身が空になり記号だけが残る場合は拒否する
- **セル内の `<br>` の削除**：`<br>` の直後でBackspace、直前でDeleteを押すと、その `html_inline` トークンの記録済み範囲だけを削除する。キャレットのある側にだけ文字ランがあればよく、セルの先頭・末尾の `<br>` や、連続する `<br>` の一つも削除できる。再解析で、その `<br>` トークンだけがなくなり、ほかのインライン構造が保たれ、表示文字が「前の文字＋後の文字」（片側がなければ残った側の文字だけ）になることを確かめる。ゼロ長ランだけのセルで隣の `<br>` を消す操作も同じ条件で扱う。`<br>` 以外のHTML、セルの外への境界削除は従来どおり拒否する。削除後は結合した位置へカーソルを置く。Ctrl+Z一回で削除前に戻せる

### 7.5 検証の条件

通常の文字編集は、書き換え後の解析結果が次をすべて満たす場合だけ採用する。改行は上記の専用検証で許可した構造変化だけを認める。

- ブロックトークンの種類と並びが変わっていない（スライド枚数、見出しのレベル、リストの構造を含む）
- 編集したブロックのインライントークンの種類と記号（`**`、`_` など）の並びが変わっていない
- 編集したランの表示文字が、ユーザーの入力結果と一致する（ブロックの先頭・末尾の空白の違いは許す）
- ほかのランの表示文字は変わっていない

これにより、行頭に `#` や `1.` を入力して見出しやリストに変わってしまうこと、`*` の入力で強調が崩れることを防ぐ。

### 7.6 元に戻す・やり直す

- 編集中も非編集時も、Ctrl+Z / Ctrl+Y はアプリの履歴で処理する（ブラウザ標準の履歴はモデルとずれるため使わない）
- 元に戻した後は再描画し、記録したカーソル位置に戻す

### 7.7 P0で読み取り専用にするもの

最上位要素（段落、見出し、リスト、引用、表、コードブロック、単独画像）は選択および削除の対象にできるが、コードブロックや数式の中身、インラインコード、HTMLブロック、絵文字、front matter、ディレクティブのコメント、Marp Coreが自動生成するヘッダー・フッター・ページ番号は文字編集としては読み取り専用とする。読み取り専用の要素をクリックした場合は要素を選択し、ステータスバーに理由を表示する。
表は7.4のセル内文字編集および7.11の行・列編集に対応するが、配置（`:---:`）の変更や条件を満たさない表・セルは読み取り専用のままとする。
画像は7.12の挿入・大きさ変更および選択・削除に対応するが、文章の途中の画像、リンクで囲んだ画像、`bg` キーワードを含む背景画像、および代替テキストが条件を満たさない画像は読み取り専用とする。
ヘッダー・フッターは `header:` などのディレクティブ値であり、P1で編集対応を検討する。

### 7.8 スライドの追加・削除・並べ替え

一覧下部の＋、右クリックメニュー、一覧にフォーカスがあるときのCtrl+M（追加）、Ctrl+D（複製）、Delete / Backspace（削除）、Ctrl+↑ / Ctrl+↓（移動）で要求する。Ctrl+Mは文字編集中でなければ一覧外でも利用する。右クリックは対象を選択してからメニューを開き、↑↓・Enterで選択、Escまたは外側のクリックで閉じる。メニューは画面内に収め、ショートカットを右側に表示する。読み取り専用・最後の一枚の削除・端を越える移動は無効にし、その他の拒否理由はAppの通知へ渡す。

Appの各 `TabWorkspace` は、アクティブなタブでIME確定を待ち、セッション・タブ・外部変更・保留状態を再確認してから文字編集を終了し、セッションのスライド操作を呼ぶ。成功時は更新済みの解析と描画を使って選択スライド・一覧・保存状態を更新し、拒否理由はステータスバーへ表示する。読み取り専用・未解決の競合・確認や更新インストール中は操作しない。一覧外のCtrl+Mも同じ経路を使い、入力欄・文字編集中・IME変換中や他の修飾キーとの組み合わせでは実行しない。Undo/Redoは編集終了後の履歴の有無で判定し、正規化本文が同じで改行情報だけが変わる履歴も再解析・再描画する。スライド操作の履歴に記録した `Cursor.slideIndex` から操作前後の選択を復元する。

サムネイルはポインターを4px以上動かすとドラッグを開始する。行間の2pxのアクセント線で挿入先を示し、一覧の上下端付近で自動スクロールする。Escで取消し、移動先が変わらなければ何もしない。既存の行・番号・選択枠・選択追従スクロールを維持する。一覧は操作コールバックと読み取り専用状態だけを受け取り、IME待機・編集終了・モデル更新・拒否通知はAppが担当する。

複数範囲の履歴は改行情報付きの `DocumentModel.editTransaction` に統一する。箇条書きの階層変更も降順の範囲配列を返し、従来のStageコールバックが渡す配列も同じトランザクションへ委譲する。

編集エンジンは解析時に各スライド本文とMarpitの改ページhrの一意なソース範囲を記録する。front matterは範囲外とする。`headingDivider` がある文書、境界が一意でない文書、および後続スライドへ継承するディレクティブやscopedでないstyleを含む対象の操作は拒否する。
文書内のstyleディレクティブや `<style>`（scopedを含む）に、id属性・ページ番号・子要素の位置などスライドの番号や順番に依存するセレクタがあれば、追加・複製・削除・移動を拒否する（テーマCSSは対象外）。

追加・複製・削除・移動は記録済み範囲だけを置換し、複数範囲の置換もDocumentModelの一回の履歴にまとめる。追加は指定スライドの直後に空のスライドを作り、区切りは空行を前置した `---` とする。複製は本文をそのまま写す。削除は本文と隣接する区切り（先頭なら後ろ、それ以外は前）を消し、最後の一枚は削除しない。移動は区切りを位置に残して本文を入れ替える。front matterは移動・削除しない。

本文の移動・複製には元のEOL配列も引き継ぎ、BOMと未変更範囲を保持する。新規改行は近接する区切り行のEOL（区切りがなければ文書の優勢なEOL）を使う。移動・複製で区切りの前へ置く本文には、区切りとの間に空行ができるよう必要な改行だけを足し、EOL配列にも記録する（末尾改行がなければ2つ、1つなら1つ）。文書の最後へ置く本文や動かない本文の末尾は変えない。追加する区切りも直前の本文と空行で分ける。操作対象や削除範囲にグローバル／継承ローカルディレクティブ、scopedでないstyleがあれば拒否する。

操作後に同じエンジンで再解析・再描画し、旧新スライドの対応を検証する。sectionの属性・class・styleと内容を比較し、編集用の印、ページ番号、既定のsection番号、重複順序で変わる生成見出しID、scoped styleの乱数キーを正規化する。描画が変わる対応や境界を検証できない操作は採用せず理由コードを返し、元の解析を維持する。APIは操作後に選択する0始まりのスライド番号と対応表を返す。セッション層で履歴・描画結果をまとめて更新する。呼び出し側は先にIMEを含む文字編集を確定する。空の見出しに既存の永続的な編集先はないため、新規スライドは仮文字を置かず空とする。

### 7.9 要素の選択と削除

スライド本文の最上位ブロック要素を選択し、Delete / Backspace で削除できるようにする。

#### 要素の定義
- 「要素」はスライド本文の最上位ブロック（リストや引用などのコンテナの外で、字下げのないブロック）を指す。対象の種類は、段落、見出し、リスト（最上位のリスト全体）、引用（全体）、表、コードブロック、画像、テキストボックス（7.13）とする。
- 画像要素は、段落の中身が画像1つだけ（前後の空白は許容）の段落とする。文章の途中の画像、リンクで囲まれた画像、`bg` キーワードを含む背景画像は要素とせず、従来どおり読み取り専用とする。
- HTMLブロック（テキストボックスを除く）、コメント（ディレクティブ）、front matter は要素としない。

#### 範囲の記録
- 解析時に各最上位ブロックトークンの `map` から、ソースの行範囲 `[開始行の先頭, 終了行の改行の後)` を記録する。7.8 のスライド本文範囲に含まれることを確認する。
- 範囲を一意に決定できない要素、スライド境界をまたぐ要素、コメントやHTMLを含む要素は、選択は可能とするが削除は拒否し理由を表示する（理由コード：`element-ambiguous`、`element-structure-changed` など）。
- `headingDivider` が有効な文書では、7.8 と同様に要素の削除・挿入を拒否する（理由コード：`element-heading-divider`）。

#### 選択の操作
- 画像をクリックすると、その画像要素を選択する。
- 文字の編集中に Esc を押すと、編集を確定・終了し、その文字を含む最上位要素を選択する（表のセル編集中なら表全体を選択する）。要素の選択中にもう一度 Esc を押すと選択を解除する。これは従来の「Esc＝編集を終了してフォーカスを外す」を変更するものである。
- 読み取り専用の要素（コードブロックなど）をクリックすると、その要素を選択し、ステータスバーに理由を表示する。
- 選択の解除は、Esc、要素のない場所のクリック、別の要素のクリック、スライドの切り替えによって行う。
- 選択中の要素には、アクセント色の2pxの枠を表示する。画像要素の場合は四隅に大きさ変更のハンドルを表示する。

#### 削除の処理と検証
- 選択中に Delete または Backspace を押すと要素を削除する。
- 削除する範囲は、要素の行範囲と直後の空行（次のブロックの手前まで）とする。ただし、要素がスライド本文の最後のブロックである場合は直後の空行を残し、代わりに直前の空行（前のブロックの後ろから）を削除する。スライド内の唯一のブロックである場合は、要素の行範囲のみを削除する。これにより、区切り `---` の直前の空行を保ち、段落が見出しの下線記法に化けることを防ぐ。
- 削除後のソースを再解析して検証する。検証条件は次のすべてを満たすこととする：
  - スライド枚数が変化しないこと
  - 他のスライドの描画結果が変わらないこと（7.8 と同じ正規化による比較）
  - 対象スライドのブロックの並びが、元のブロック並びから対象要素を除いたものと完全に一致すること
  - 他のブロックの表示文字が変わらないこと
  - 段落の削除によって前後の同じ記号のリストが結合するなど、Markdownの構造変化が起きないこと（構造変化が起きる場合は拒否し、理由コード `element-structure-changed` を表示する）
- 削除は1回の範囲置換として DocumentModel の履歴に記録し、Ctrl+Z 1回で復元できるようにする。
- 削除後は選択を解除して再描画し、サムネイルも更新する。
- 読み取り専用の文書（帯が出ている状態）や未解決の競合中は削除を実行せず拒否する（理由コード：`element-readonly`）。

### 7.10 ブロックの挿入

表や画像の挿入における共通のブロック配置・改行処理と検証を定義する。

- **挿入位置**：選択中の要素があればその直後とする。文字の編集中であれば、編集を確定・終了してからその文字を含む最上位要素の直後とする。いずれも選択されていない場合は、表示中のスライド本文の末尾（空のスライドならスライド区切りの後）とする。
- **改行と空行の確保**：新しいブロックの前後に1つ以上の空行ができるよう、必要な改行のみを挿入する。既存行の内容は変更しない。ファイル末尾に改行がない場合は、まず末尾に改行を1つ追加する。
- **改行コードの統一**：追加する改行コードは隣接行の改行コード（隣接行がなければ文書内で優勢な改行コード）に合わせ、EOL配列に記録する（7.8 と同様）。
- **検証**：挿入後のソースを再解析し、次のすべてを満たすことを検証する：
  - スライド枚数が変化しないこと
  - 他のスライドの描画結果が変わらないこと
  - 対象スライドのブロックの並びが、指定位置に新しいブロックが1つ増えたものと一致すること
  - 他のブロックの表示文字が変わらないこと
- 挿入処理は1回の範囲置換として DocumentModel の履歴に記録する。
- 挿入後は再描画を行い、表の挿入であれば左上のセルにカーソルを置いて文字編集を開始し、画像の挿入であれば画像を選択状態とする。
- 読み取り専用の文書、未解決の競合中、または `headingDivider` が有効な文書では挿入を拒否する（理由コード：`element-readonly`、`element-heading-divider`）。

### 7.11 表の挿入と行・列の編集

スライド上に新しい表ブロックを挿入し、既存の表に対して行や列の挿入・削除を行えるようにする。

#### 表の挿入
- ツールバーの「表」ボタンを押すと、最大10列×8行のマス目ポップアップを開く。ポインターの移動で大きさを選択し、クリックで挿入する。上部に「3 × 4 の表」のように選択中の行列数を表示する。矢印キーによるサイズ変更、Enter での挿入、Esc での中止に対応する。
- 指定行数は見出し行を含み、最小サイズは2行×1列とする。
- 挿入するソースは全セルが空の表とする。例（3列×2行）：
  ```markdown
  |  |  |  |
  | --- | --- | --- |
  |  |  |  |
  ```
  空の見出しセルがGFM表として正しく解析され、7.4 の空セル（ゼロ長ラン）として文字入力できることをテストで検証する。

#### 対象とする表の条件
- 7.4「表のセルの文字」の条件を満たす最上位の表であり、かつ全行が行頭と行末に `|` を持ち、全行のセル数が見出し行のセル数と一致し、`\|` を含まない表を対象とする。
- この条件を満たさない表では、行・列編集のメニュー項目を無効化し、理由を表示する（理由コード：`table-unsupported`）。

#### 行・列の追加と削除
- 表のセルを右クリック（セル編集中、または表の選択中）するとコンテキストメニューを表示する。メニュー項目は「上に行を挿入」「下に行を挿入」「左に列を挿入」「右に列を挿入」「行を削除」「列を削除」「表を削除」とする。見た目とキーボード操作（↑↓・Enter・Esc）はスライド一覧の右クリックメニューと統一する。
- **見出し行の制限**：見出し行での「上に行を挿入」「行を削除」は無効とする（GFMでは見出し行は1行のみのため。表全体の消去には「表を削除」を使用する。理由コード：`table-header-row`）。見出し行での「下に行を挿入」は、区切り行の直後に本文行を挿入する。
- **列削除の制限**：列が1列のみの場合、「列を削除」は無効とする（理由コード：`table-last-column`）。
- **本文行の削除**：本文行がすべてなくなる行削除は許容する（見出し行と区切り行のみの表となる）。
- **行の挿入**：対象行の行範囲の直後（上への挿入なら直前）に、空セルの行（`|  |  |`）と改行を挿入する。改行コードは対象行のものに合わせる。
- **行の削除**：対象行の行範囲（改行を含む）を削除する。
- **列の挿入**：各行（区切り行を含む）において、`escapedSplit` と同じ規則で記録した各セルの境界 `|` の位置に、空セル `  |`（区切り行は ` --- |`）を挿入する。新しい列の配置は指定なしとする。
- **列の削除**：各行において、対象セルと右隣の `|` を削除する（最終列の場合は左隣の `|` と対象セルを削除する）。
- 他の列のアライメント（`:---:`）や既存セルの空白（桁揃え）は維持する。
- 列の挿入・削除に伴う複数箇所の範囲置換は、元の解析座標で記録し、後方から順に適用して `DocumentModel.editTransaction` による1回の履歴にまとめる。
- **検証**：再解析を行い、表の行数または列数が意図どおり1だけ増減し、対象外の行・列のセルの表示文字と配置、および他のブロックの内容が変わらないことを確認する。
- 操作後は再描画し、挿入操作の場合は新しく追加された行・列の対応するセルにカーソルを配置する。削除操作の場合は表を選択状態とする。

### 7.12 画像の挿入と大きさ変更

画像ファイルを安全に取り込んでスライドに挿入し、選択ハンドルのドラッグによって表示サイズを変更できるようにする。

#### 画像の挿入
- ツールバーの「画像」ボタンを押すと、OSのファイル選択ダイアログ（対応拡張子：`png` / `jpg` / `jpeg` / `gif` / `webp`）を開く。非対応の形式が選択された場合は拒否する（理由コード：`image-unsupported-type`）。
- **パス解決とファイル配置**：
  - 選択された画像が開いている `.md` ファイルと同じフォルダまたはそのサブフォルダ配下にある場合は、ファイルをコピーせず相対パスを使用する。
  - それ以外の場所にある画像は、`<.mdのフォルダ>/images/`（存在しない場合は自動作成）へコピーする。同名のファイルが既に存在する場合はファイル内容を比較し、内容が同一であれば既存ファイルを再利用する。内容が異なる場合は `name-2.png` のように連番を付与し、既存ファイルを上書きしない。コピー処理は一時ファイルに書き出した後にリネームすることで安全に行う（失敗時の理由コード：`image-copy-failed`）。
  - コピー先のファイル名は、Markdownで構文上の問題を引き起こす文字（空白、`( ) < > [ ] # % ? \`、制御文字）を `-` に置換して正規化する。日本語などのUnicode文字はそのまま維持する。
  - `.md` フォルダ配下の既存パスに空白などが含まれる場合はパーセントエンコードを行ってソースに記述する。アプリ上での相対パス解決およびPowerPoint書き出しの両方で表示可能であることをテストで確認する。
  - 画像の安全なコピー処理のため、Rust側に新コマンド `import_image(md_path, source_path) -> 相対パス` を追加する。保存（`files.rs`）やファイル監視（`watching.rs`）の既存処理は変更しない。
- **ソースの記述形式**：画像1つだけを含む単独の段落として挿入する。代替テキストは空（`![](パス)`）とする（ファイル名等を代替テキストに入れると、Marpの `bg` などのキーワードとして誤解釈される恐れがあるため）。
- **初期サイズ**：画像の元サイズがスライド幅の80%かつ高さの60%に収まる場合は `![](パス)` とする。収まらない場合は、縦横比を維持してスライド幅80%または高さ60%に収まるよう縮小した幅（px、整数値）を計算し、`![w:幅](パス)` として記述する。

#### 大きさの変更（リサイズ）
- 選択された画像の四隅にリサイズハンドルを表示する。ハンドルをドラッグしている間は、画面上の画像要素のみを縦横比維持で拡大縮小表示する。マウスボタンを離した時点で、Markdownソースを1回の範囲置換で書き換える。
- 代替テキスト内の `w:` / `width:` の記述範囲を解析時に記録しておき、その値をドラッグ後の新しい幅（整数値px）に置き換える。代替テキスト内に幅指定が存在しない場合は、代替テキストの先頭に `w:幅`（後ろに既存のテキストがあれば空白1つを付与）を挿入する。代替テキスト内に `h:` / `height:` が存在する場合は、縦横比を固定維持するためにその指定を削除する。
- 設定可能な幅の制約は、最小16px以上、最大スライド幅以下とする。
- 代替テキスト内に `\` のエスケープが含まれる場合や、ソースと表示が1対1に対応しない場合は、大きさ変更を拒否する（理由コード：`image-unsupported-alt`）。
- **検証**：再解析を行い、同じ段落内に画像が1つだけ存在し、ソースの `src` が不変で、幅指定が新しい値に更新され、他の要素や構造が変わっていないことを確認する。
- ドラッグ中に Esc を押した場合は、リサイズ操作を取り消して元の大きさに戻す。

### 7.13 テキストボックス

#### ソースの記述形式
- テキストボックスは、開きタグの行と閉じタグ `</div>` の行で、中身を空行をはさんで囲む形で記述する。
  ```html
  <div data-box style="position:absolute; left:320px; top:240px; width:640px; font-size:32pt">

  ここに文字。**太字**やリストも書ける

  </div>
  ```
- 中身は通常のMarkdownとして解析されるため、既存の直接文字編集（7.4）がそのまま使える。
- 座標はスライドの座標系（既定で 1280×720）の px とする。`left`、`top`、`width` は整数の px、`font-size` は整数の pt（PowerPointと同じ単位。CSS の pt をそのまま使用）とする。`font-size` は省略可能であり、省略時はテーマの既定の大きさとなる。
- `position:absolute` はソースに記述する。Marp CLI（`--html`）や VS Code（HTML有効時）でも、アプリと同じ位置に表示させるためである。
- 箱を書く位置はソース上でどこでもよい（絶対配置のため、ソースの順番は表示位置に関係しない。後ろに書いた箱ほど前面に表示される）。
- 実装時に、Marp CLI の `--html`、VS Code の Marp 拡張（HTML有効）、アプリの3つで同じ位置・大きさに表示されることを確認する。Marp のスライド（`section`）が絶対配置の基準にならない場合は、対処方法を設計書に追記してから実装する。

#### HTMLの許可と安全性
- Marp Core の `html` オプションに許可リストを渡し、`div` だけを追加で許可する。属性は `data-box` と `style` のみとする。
- `style` は属性値の検査関数で、上記の書式（`position:absolute` と、`left`、`top`、`width` の整数 px、省略可能な `font-size` の整数 pt、順番固定、空白の有無は許容）に完全に一致するときだけ通し、それ以外は空にする。
- それ以外のHTMLは従来どおり通さない。`html: true` は使わない。
- プレビュー、サムネイル、PowerPoint書き出しで同じ許可リストを使う（書き出しの既存の図用許可リスト `svgHtmlAllowlist` と合わせる）。

#### テキストボックスの認識
- 解析時に、最上位の `html_block` のうち、開きタグの行が上記の書式に完全に一致するものと、その後ろで最初に現れる `</div>` だけの行の `html_block` を組にする。
- 間に別の `div` がある、同じスライドに閉じタグがない、書式が一致しない、のいずれかの場合は箱として扱わない（`div` の行は従来どおり読み取り専用のHTMLとし、中の段落は通常どおり編集できる）。
- 箱の中の要素は、箱の外と同じように直接編集できる。7.9 の「要素」としては、箱全体（開きタグの行から閉じタグの行まで）を1つの要素「テキストボックス」として扱う。箱の中の文字を編集中に Esc を押すと箱を選択する。
- 箱の入れ子は行わない。

#### テキストボックスの挿入
- ツールバーの「テキストボックス」ボタンで、表示中のスライドの本文の末尾に、空の箱を挿入する（7.10 の基盤を使う）。
- 位置はスライドの中央付近とし、幅はスライド幅の50%、左右中央、上端はスライド高さの40%とする。`font-size` は書かない。
- 空の箱は、中身の行1つを空行ではさんだ形で挿入し、その行の挿入点にゼロ長の文字ランを作ってすぐに入力を始める（7.4「末尾の空の編集先」と同じ考え方）。
- 何も入力せずに編集を終えたら（Esc、ほかの場所のクリック、スライドの切り替えなど）、箱の挿入を取り消す。7.4 の空の段落と同じく、この仮の挿入は最初の文字入力までは履歴に入れず、最初の入力で「挿入＋文字」を1回の履歴として確定する。
- 入力済みの箱の中身をすべて消した場合は、箱は残す（PowerPointと同じ）。箱を消すには選択して Delete を押す。

#### 移動と幅の変更
- **選択のしかた**：
  - テキストボックスにポインターを重ねると、点線の枠を表示する。枠の上（内外 6px の帯）をクリックすると箱を選択し、そのままドラッグすると移動する。
  - 箱の中の文字の編集中に Esc を押すと箱を選択する（7.9 と同じ）。
  - 選択中の要素の上を押して動かすとドラッグで移動する。動かさずに離した場合は、その位置で文字の編集を始める。
- **移動**：
  - ドラッグ中は画面上の表示だけを動かし、離したときに `left` と `top` の数値の範囲だけを書き換える（1回の範囲置換、1回の履歴）。Esc でドラッグを取り消す。
  - 選択中は矢印キーで 10px、Shift+矢印キーで 1px 動かす（このとき矢印キーのスライド移動は行わない）。連続したキー操作も1回ずつ履歴に入れる。
- **幅の変更**：
  - 選択中の箱の左右の辺の中央にハンドルを出し、ドラッグで `width`（左のハンドルなら `left` も）を変える。高さは中身に合わせて自動とする。幅は 40px 以上とする。
- 箱がスライドの外へ完全に出ないよう、少なくとも 16px はスライド内に残るように位置を制限する。
- 画面上の拡大縮小（スライドを画面に合わせて縮めて表示している分）を考慮して、ポインターの移動量をスライドの座標系の px に換算する。値は整数に丸める。
- **検証**：再解析して、箱の組と中身のブロックの並び・表示文字が変わらず、`style` の値だけが意図どおりになっていることを確認する。通らなければ拒否して理由（`box-move-failed`）を表示する。

#### 既存要素の自由配置への変換
- 箱ではない最上位要素（段落、見出し、リスト、引用、表、画像、コードブロック）を選択してドラッグすると、その要素を箱で囲んで自由配置にする。
- **ソースの書き換え**：要素の行範囲の直前に開きタグの行と空行、直後に空行と閉じタグの行を挿入する（要素のソース自体は動かさない、変えない）。必要な空行・改行コードは 7.10 と同じ規則で足す。1回の履歴にまとめる。
- **箱の初期値**：`left`、`top`、`width` は、ドラッグを始める前に画面上で測った要素の位置と幅（スライドの座標系の px、整数）にドラッグの移動量を足したものとする。`font-size` は書かない。
- 箱にすると要素は本文の流れから外れるため、後ろの要素は上に詰まる（ドラッグ中の表示もこの結果に合わせる必要はなく、離した後の再描画で反映する）。
- **検証**：再解析して、スライド枚数、他のスライドの描画、要素自身と他の要素の表示文字とブロックの並び（追加した2つの `div` の行を除く）が変わらないことを確認する。通らなければ拒否して理由（`box-convert-failed`）を表示する。
- `headingDivider` がある文書では拒否する（7.9 と同じ）。
- 箱を外して元の流れに戻す操作は今回は行わない（P1）。

### 7.14 文字の大きさ

- ツールバーに「文字サイズ」の選択欄を置く。選択肢は、既定、12、14、16、18、20、24、28、32、36、40、44、48、54、60、72（単位 pt）とする。
- テキストボックスを選択中、または箱の中の文字の編集中だけ有効とする。箱全体の大きさが変わる（箱の中の一部の文字だけを変えることはしない）。
- 箱ではない要素を選択・編集しているときは無効にし、ツールチップで「テキストボックスで変更できます」と伝える。
- 選択肢を選ぶと、`style` の `font-size` の範囲だけを書き換える。属性値に `font-size` がなければ `width` の後ろに追加し、「既定」を選んだら `font-size` を削除する。1回の範囲置換、1回の履歴とする。
- 現在の値を文字サイズの選択欄に表示する（設定されていなければ「既定」と表示する）。

### 7.15 太字の付け外し

- ツールバーの「B」ボタン、または文字の編集中の Ctrl+B で、選択した文字の太字を付け外しする。テキストボックスの中でも外でも使える。
- **付ける**：選択範囲が1つの文字ランの中に収まり、太字の中でない場合、選択範囲の前後に `**` を挿入する（2か所の範囲置換を1回の履歴にまとめる）。選択範囲の前後の空白は太字に含めない。
- **外す**：選択範囲（またはカーソル位置）が既存の太字（`**…**` または `__…__`）の中身とちょうど一致するか、カーソルが太字の中にある場合、その太字の記号の2か所だけを削除する。
- 次の場合は操作を拒否して理由を表示する：
  - 選択範囲が複数の文字ランや装飾にまたがる（`bold-multiple-runs`）
  - 太字の一部だけを選んでいる（`bold-partial`）
  - 選択範囲が空で太字の中でもない、または `**` を入れると Markdown の規則（前後の文字や記号との組み合わせ）で太字として解析されない（`bold-invalid-position`）
- **検証**：再解析して、表示文字が変わらず、インラインの構造が「対象の範囲に太字が1つ増えた（または減った）」だけであることを確認する。
- 付け外しの後は、同じ文字範囲を選択した状態に戻す。
- 「B」ボタンは、カーソルが太字の中にあるときに押された状態で表示する。
- 従来、編集中の Ctrl+B などの書式変更は止めて理由を表示していた（7.4）。Ctrl+B だけはこの機能に置き換える。Ctrl+I などほかの書式変更は従来どおり止める。

#### 要素ごとの太字

- 要素（7.9）を選択した状態で「B」ボタンまたは Ctrl+B を押すと、その要素の中の文字全体の太字を付け外しする。文字を範囲選択しなくてよい。
- 対象の要素：テキストボックス、段落、見出し、リスト、引用、表。コードブロックと画像の選択中は「B」ボタンを無効にする。
- 要素の中の「文字のまとまり」（段落、見出し、リストの各項目、表の各セルのインライン部分）ごとに処理する。空のまとまり（空のセルなど）は対象外とする。
- すべてのまとまりが、中身全体を1つの太字（`**…**` または `__…__`）で囲まれている場合は、それらの太字の記号だけを削除する（太字を外す）。
- それ以外（太字がない、または一部だけ太字）の場合は、まとまりの中の既存の太字の記号を削除してから、各まとまりの中身全体を `**` で囲む（全体を太字にする。PowerPointと同じ動き）。中身の前後の空白は太字に含めない。
- 記号の位置は解析時に記録したインライントークンの範囲から取り、文字列検索で探さない。すべての範囲置換を DocumentModel.editTransaction の1回の履歴にまとめる（Ctrl+Z 一回で戻る）。
- **検証**：再解析して、表示文字が変わらず、各まとまりのインラインの構造が「中身全体が1つの太字」（または「太字がない」）になっていて、ほかの構造が変わらないこと。1か所でも太字として解析されない、または検証に通らない場合は、操作全体を行わず、理由 `bold-invalid-position` を表示する。
- 「B」ボタンは、選択中の要素のすべてのまとまりが太字のとき、押された状態で表示する。
- 操作の後も同じ要素を選択した状態に戻す。

## 8. PPTX書き出し（`src/export/pptx`）

### 8.1 方式

Marp CLIの `--pptx` は各スライドを画像にするため編集できない。`--pptx-editable` はLibreOfficeが必要で、レイアウトの再現も限定的である。
そこで本アプリは、**アプリ内で描画済みのスライドDOMを実測し、PowerPointの部品に組み立て直す**。
位置・大きさ・文字のスタイルは計算済みの値（`getBoundingClientRect`、`getComputedStyle`）から取るため、テーマやカスタムCSSが効いた最終結果をそのまま反映できる。

### 8.2 処理の流れ

1. 書き出し用に、画面外の非表示コンテナで全スライドを等倍（例：1280×720px）で描画する。自動縮小（`<!-- fit -->`）やフォントの読み込み完了を待つ
2. スライドごとにDOMを上から順にたどり、要素を次のように分類する
   - **テキストボックス・文字ブロック**（7.13 のテキストボックス、`h*`、`p`、`li`、`blockquote`、ヘッダー・フッター）→ テキストボックス。テキストボックスは PowerPoint のテキストボックスとして位置・幅・文字の大きさを反映する。書き出しは画面上の配置を実測する方式のため、追加の処理が不要か実装時に確かめ、必要な場合だけ対応する
   - **表** → PowerPointの表
   - **画像** → 画像
   - **単色の箱** → 塗り・罫線付きの図形。均一な円形の角丸は `roundRect` とし、半径を実測値で指定する。非対称・楕円・複雑な装飾は箱の背景だけ画像化する
   - **SVG図** → `g`、`rect`（`rx`対応）、単純な `text`、`M/L/H/V` の直線パス、三角形の矢印マーカーをネイティブ図形へ変換する。画面座標変換を適用し、未対応要素・塗り・変形・クリッピングがあれば、途中の図形を破棄して当該SVGだけ画像化し理由を記録する
     - パスのサブパス境界と `Z/z` の閉路を解析する。接続する複数線分や閉路はサブパスごとに編集可能な自由形状（`custGeom`）にする。PptxGenJS 4.0.1に接合方式の指定APIがないため、既存のOOXML補正で対象図形のみに `miter`（miterlimitを含む）・`round`・`bevel` と平坦な端点を指定する。線幅による画像化は行わず、線と接合の描画範囲がSVG表示枠で切れる場合は画像化する。独立した直線サブパスは従来の直線図形を維持する。SVG仕様に従い、`marker-end` はpath全体の最終点だけに生成する。`marker-start/mid` はプレビューと書き出しの許可リストで保持し、未対応のためSVG単位で画像化する
     - 半透明の線（`stroke-opacity` または線色のalpha）を持つ複数サブパスのpathは、SVG単位で画像化し理由を記録する。同一pathの線を別図形に分割すると重なりの透明度が二重に適用されるため。不透明な線と、別々のpath要素が独立して重なる描画は従来のネイティブ変換を維持する
     - 塗りのある直線パスは、すべてのサブパスで全頂点が同一直線上にあり、暗黙に閉じても面積が生じない場合だけ塗りを無視する。既定の黒も同様に扱う。判定は画面座標変換前の有限なIEEE 754座標を共通単位（2^-1074）のBigIntへ変換し、外積を厳密に比較する。許容誤差は設けず、わずかな非共線も画像化する。符号付き面積の相殺だけでは許可しない。L字、三角形、自己交差など面積のある塗りはSVG単位で画像化する
     - 参照変換と同じ表示にするため、SVG文字の字面が表示枠を3 CSS px以内だけ越える場合はネイティブ文字を維持し、近似として記録する。それを越える切り取りや文字以外の切り取りは画像化する
     - 生のSVGを使う場合は、プレビューと書き出しのMarpに同じ `svgHtmlAllowlist` を指定する。任意HTML・スクリプトは有効にしない。標準許可リストのままではSVGはエスケープされる
   - **背景**（`section` の背景色・背景画像、`bg` 分割の `figure`）→ スライド背景または最背面の画像
   - **再現できないもの** → 画像化（8.4）
3. 座標をpx→インチに変換し（スライド幅 ÷ 描画幅）、PptxGenJSで組み立てる
4. Marpのコメント（発表者ノート）をスライドノートに入れる
5. `write_binary` で保存する。保存後は画像化やフォント代用があった場合だけ、スライドごとの件数やフォント名を日本語で簡潔に知らせる。画像内の文字はPowerPointで編集できないことも伝える。通常の近似は利用者へ表示しない。エラー・警告は意味の分かる日本語で示し、内部診断は「詳細」の折りたたみ内に置く。問題がなければダイアログを出さず、書き出したファイル名をステータスに表示する

### 8.3 文字の変換

- 段落ごとに、文字ランを計算済みスタイル付きで集める：欧文フォント名（日本語専用の別名を除いた `font-family` の先頭で実際に使えるもの。`local()` はファミリ名と Regular のフェイス名を確認する。総称ファミリは欧文サンプルの実測幅をWindowsの候補フォントと照合する。後続をserif/monospaceに変えると幅が変わる未対応名はスキップし、後続のConsolasなどを評価する。一致しない総称名や単独の未対応総称名は、Windowsの既知フォントに近似して `substitutedFonts` に記録し、書き出しを継続する。対応表・根拠は `src/export/pptx/README.md` を参照。フォント対応づけだけを理由に全体を停止しない）、サイズ（px→pt）、色、太字、斜体、下線、取り消し線、リンク先、文字間隔
- 段落の行間（`line-height`）、前後の余白、文字の配置、インデントを反映する
- 箇条書きは記号の種類（`list-style-type`）と階層を反映する。番号付きリストは開始番号も反映する
- 入れ子を含むリスト全体を1つのテキストボックスにし、各項目を段落にする。段落の階層・記号・開始番号と、DOMで実測した本文位置・段落間隔を設定する。PptxGenJSが階層数から再計算するインデントは、生成後のOOXMLで実測値に補正する
- 入れ子のない平坦なリストは、項目ごとに実測位置のテキストボックスを使い、PowerPointの段落高の累積誤差を避ける。入れ子リストの編集単位は維持する。小さい負の文字間隔（0.05emかつ1px以内）はDrawingMLの文字間隔として保存する
- PPTXの文字ランを上記の日本語Unicode範囲の境界で分割する。`latin` は実際の欧文フォントを保持し、日本語範囲のランだけ `ea`（東アジア）を `Noto Sans JP` に補正する。注音字母・ハングルなど範囲外のランの `ea` は元のフォントを保持する。ランの装飾・リンク・改行・段落設定は維持する。日本語の箇条書き記号は `buFont` もNoto Sans JPとする。計測・画像化にもプレビューと同じ日本語専用面を適用し、フォント読み込みと自動縮小の完了後に実測する
- テキストボックスの自動調整はオフにし、DOMの実測の大きさに少し余白を足す（折り返し位置の差による溢れを防ぐ）
- Marpで自動縮小済みの1行の見出しは、PowerPoint側のフォント幅の差で再び改行されないよう折り返しを無効にする
- Webフォント（`@import` のGoogle Fontsなど）は、Windowsにあればその名前、なければ近い代替（例：Lato → Segoe UI。日本語は常にNoto Sans JP）で書き出し、一覧に記録する
- 表のセル余白はDOMのpaddingをインチで渡し、行高はDOMの実測値を指定する。列幅は実測した各行の文字幅と余白にOfficeのフォント差の予備幅を加えた最小幅を確保する。予備幅で表全体が広がり、祖先の内容領域を越えることは許容する。スライド右端を越える場合だけ、余裕のある列から幅を配分し、それでも足りない予備幅を比例して縮める。予備幅不足だけでは画像化しない。英語・日本語の代表例はPowerPoint本体で検証し、mainとの行高の差を記録する
- 単色で矩形のセル背景は表セル自身の塗りとする。ただし、表内の子孫に背景・枠線・疑似要素などの独立した装飾がある場合は、表全体のセル塗りを透明にし、「セル背景の図形 → 子孫の装飾 → 透明な表」の順に重ねる。セル背景の図形と表・行・列・グループの単色背景は、同じ最終列幅から求めた境界へ写像する。角丸・グラデーション・影などの装飾は従来の別画像を維持する。元のDOMの表自体がスライドの左右端からはみ出す場合は、表全体を画像化し、理由を記録する

### 8.4 画像化

PowerPointの部品で再現できない要素（数式、絵文字、未対応のSVG、グラデーション文字、影・変形、`::before` / `::after` の装飾、複雑な背景）は、その要素の範囲をPNGにして同じ位置に貼る。

- 方式：要素をSVGの `foreignObject` に複製してcanvasに描画する（`html-to-image` 相当の処理）
- 資産URLの画像は、canvasが汚染されないよう事前にdata URLへ変換する
- 透明部分を保ち、高解像度（2倍）で出力する

**技術的な確認事項（実装の最初に検証する）**：WebView2上で `foreignObject` → canvas の画像化が、Tauriの資産URL・Webフォント・Marpのテーマで正しく動くか。動かない場合は、Rust側でWebView2の `CapturePreview` を使い、画面の該当範囲を切り出す方式に切り替える。

2026-10-22の検証結果：実際のTauriアプリをWebView2（Chromium/Edge 155）で起動し、CDPからdefault / gaia / uncover、日本語、表、入れ子リスト、左右の背景分割、MathJax、SVG、独自テーマをPPTXへ出力した。資産URLのPNG・SVGを事前にdata URLへ変換するとcanvas汚染は起きず、数式と透過PNGも描画できた。data URLで埋め込んだWebフォントも画素が出ることを確認したため、`CapturePreview` は使わない。再実行用の入口は `tests/export/webview2.mjs`。

- `html-to-image.toPng()` は非表示ウィンドウで `requestAnimationFrame` 待ちになるため、`toSvg()` の後に `Image.decode()` とcanvasを直接使う。
- Marpのコード・自動縮小はShadow DOM内のSVGとslotを使う。画像化の直前だけSVG内のslotを計算済みスタイル付きの内容へ展開し、終了時に戻す。展開しない場合にコードの文字だけが欠落する問題を確認し、実画像の構文色の画素を検査する回帰チェックを追加した。編集可能な自動縮小見出しはSVGの実倍率を文字サイズに反映する。
- 現在のCSPの `connect-src` は外部フォントのfetchを許可しない。取得できないフォントはローカルのフォールバックで計測し、代替名と警告をレポートする。あらかじめ埋め込んだ `fontEmbedCSS` もAPIで受け取れる。Webフォントの外部取得を有効にする場合は、UIへの組み込み時にフォント配信元をCSPへ追加する必要がある。
- Element measurement and native conversion are isolated: unexpected geometry or unsupported style values rasterize only the affected element. Raster/asset failures are recorded with slide and element context in the report (and completion warnings); unaffected elements and slides still export.

- Native conversion is allowed only for explicitly allowlisted structures and computed style values verified in PowerPoint. All collectors share an ancestor-aware painted-state check, including hidden/content-visibility, visibility and empty boxes. Nonrectangular tables (hidden rows/cells/columns or spans) rasterize as a unit; unknown values never receive a guessed default. DOM-independent classification records why inline images, images in tables, unsupported list blocks, inline decoration, and text-transform require rasterization. Hidden text is excluded from native runs; text alpha is serialized as OOXML run transparency.
- Native eligibility has three outcomes: exact mapping, an explicitly allowlisted approximation, or rasterization. `styles.ts` centrally defines bounded typography approximations (underline offset/thickness, numeric/font features, kerning, rendering/smoothing and small letter spacing) and alpha border compositing. Every applied approximation is recorded by slide, element, CSS property/value and replacement in `report.approximatedElements`. Large underline changes, negative spacing outside the bound, text/case/visibility changes, unsupported markers, inline decoration and effects still rasterize. Built-in theme headings, paragraphs, links, lists and tables remain native.
- Only inseparable section effects (transform/opacity/filter) require a full-slide raster so that backgrounds and children share the same compositing context. Generated decorations are painted alone in their original containing blocks, cropped to their visible bounds, and inserted at their before/after position; they never force native slide content to rasterize. Uncover pagination uses a lower-right triangular gradient; only the gradient and text-shadow decoration are rasterized, while the page number stays native text. Block/list backgrounds and section borders/rounded boxes are also isolated behind native content. Pseudo-element content/background/mask/border assets are embedded before cloning; an asset failure is isolated and reported with the element and pseudo-element identified.
- Raster fallback keeps the original Marp DOM/CSS formatting context and isolates other painted branches without removing their layout space. Shadow DOM/slots alone are materialized with computed styles. Generated decoration retains the full slide viewport while painting, then crops the transparent canvas to the decoration bounds.
- Raster bounds include descendant overflow and shadow/filter extents, and image placement uses those expanded bounds. The slide viewport remains the final clip.
- Repeated background-only surfaces use an export-local cache keyed by computed appearance, not slide content or pagination. Identical PNG media are stored once in the PPTX package. Table cells retain their measured top/middle/bottom vertical alignment.
- SVG viewport eligibility includes stroke and marker paint, not just DOM geometry. A solid, opaque, square rectangle whose stroke crosses the viewport by at most 1 CSS pixel can retain exact visible paint as a native fill plus clipped rectangular border strips. Rounded/dashed/translucent or larger clipped strokes, clipped paths and markers rasterize the SVG. CSS path geometry overrides, transformed/hidden marker content and nondefault path caps/joins also rasterize the SVG.
- Text and list content boxes default to top alignment, preserving spare height from height/min-height. Measured glyph/range bounds and fully occupied line boxes can use middle alignment for font leading; list padding and borders are excluded from the text content box. Table cells may have different whitespace modes, but mixed modes within one cell rasterize the table.

### 8.5 精度の検証

`tests/fixtures/export/` に代表的なスライド（3種の組み込みテーマ、カスタムテーマ、日本語、箇条書きの入れ子、表、背景分割、数式）を置く。
書き出したPPTXの各図形の位置・文字・スタイルをテストで確認し、目視確認用に PowerPoint で開いた画面とアプリ表示の比較手順を残す。
検証用APIは計測モデル・変換レポートに加えて、等倍のMarp表示PNGを返せる。個人資料はリポジトリへ取り込まず一時ディレクトリで処理し、PowerPoint COMで既存変換と新変換をPNG化して表示と編集可能な図形数を比較する。対応する回帰入力は個人情報を含まない合成fixtureで維持する。

## 9. UI設計

### 9.1 画面構成（PowerPointの標準表示を手本）

```
┌─────────────────────────────────────────────────────────────┐
│ [deck.md ● ×] [other.md ×]                              [+] │ タブバー（32px）
│ [開く][保存][↶][↷] │ [表][画像] │ [PowerPointに書き出し] │ [☀/☾][⚙] │ ツールバー（36px）
├──────┬──────────────────────────────────────────────────────┤
│ 1 ▢  │                                                      │
│ 2 ▣  │              ┌──────────────────────┐                │
│ 3 ▢  │              │                      │                │
│ 4 ▢  │              │   選択中のスライド       │                │
│      │              │   （中央に最大表示）     │                │
│      │              └──────────────────────┘                │
│ ⟨⟨   │                                                      │
├──────┴──────────────────────────────────────────────────────┤
│ C:\…\deck.md   ● 未保存   スライド 2 / 12   編集：見出し     │ ステータスバー（24px）
└─────────────────────────────────────────────────────────────┘
```

- ウィンドウのタイトル：`deck.md ● — SlideApp`（未保存時に `●`）
- ツールバーの上に高さ32pxのファイルタブを置く。タイトル・保存・履歴・書き出しはアクティブなタブを対象とする。
- ツールバーの構成：`[開く][保存][↶][↷] │ [テキストボックス][表][画像] │ [B][文字サイズ▼] │ [PowerPointに書き出し]`。ファイルが開かれていないとき、読み取り専用、競合中、または `headingDivider` が有効なときは「テキストボックス」「表」「画像」ボタンを無効化し、ツールチップに理由を表示する。テキストボックスを選択中、または箱の中の文字の編集中以外は「文字サイズ」の選択欄を無効化し、ツールチップを表示する（7.14）。
- スライド一覧：幅180px（ドラッグで変更可、折りたたみ時は0px）。各サムネイルの左に小さなグレーの番号を表示し、番号の分だけサムネイルの幅を調整する。クリックで移動し、選択中は番号をアクセント色の太字にし、約3pxの枠・行全体の薄い背景色・左端の縦帯で強調する。ライト・ダークの両方に対応し、未選択行はホバーで薄く色を変える。アニメーションは付けない。選択中のサムネイルに `aria-current` を付け、表示スライドの変更・一覧の再表示・幅変更の後は選択行全体が見える位置までスクロールする（すでに見えていれば動かさない）
- スライド表示：余白16pxを残して、縦横比を保ったまま最大に表示
- ステータスバー：ファイルのパス（クリックでエクスプローラーで表示）、保存状態、ページ番号、編集中・選択中の要素の種類または読み取り専用の理由
- 帯（ツールバーの下）：外部変更の競合、ファイルの削除、読み取り専用、更新のお知らせ。1つずつ表示する
- ファイル未選択時：中央に「ファイルを開く」ボタンと最近使ったファイルの一覧

### 9.2 競合の帯

「このファイルは外部で変更されました。」に対して次の3つの選択肢を出す。

- **ディスクの内容を読み込む**（自分の未保存の変更を捨てる）
- **自分の変更で上書き保存する**
- **比較用に別名で保存する**（自分の内容を `<名前>.mine.md` に保存してからディスクの内容を読み込む）

### 9.4 タブ

- アプリ全体はタブの順序・アクティブなパス・共通設定を持つ。各 `TabWorkspace` はセッション（モデル・履歴・テーマ・描画）、表示スライド、一覧スクロール、帯、カーソル、非同期処理の観測世代を独立して保持する。背景のワークスペースは保持し、編集面はアクティブなものだけ接続する。
- 切り替えは既存のIME保留ゲートで確定を待ち、編集をコミットしてから行う。背景の外部変更も同じ競合判定を使い、未保存なら本文を置き換えず帯とタブの警告を保持する。
- ファイル名・絶対パスのツールチップ・未保存の●・競合／削除の警告・閉じる×を表示する。クリック、中央クリック、ドラッグ並べ替え、Ctrl+Tab／Ctrl+Shift+Tab、Ctrl+PageDown／Ctrl+PageUp、Ctrl+Wに対応する。右端の+、Ctrl+O、最近使ったファイルは新しいタブを開き、Windowsで大文字小文字を区別しない同じパスは既存タブへ移動する。
- タブのキーボード操作はキャプチャ段階で処理し、既定動作と伝播を止めて編集面へ届けない。切り替え前の文字のコミットは既存の切り替え経路で行う。
- 未保存タブの閉じる操作は保存／保存しない／キャンセルを確認する。ウィンドウ終了・更新インストールではタブを順に確認し、途中のキャンセルでは操作全体を中止する。確認／保存中は切り替えない。
- タブのパスの並びとアクティブなパスを設定へ保存し、起動時に復元する。復元時に開けないパス（削除・読取失敗）は除外する。未保存の本文は設定に保存しない。最近使ったファイルの記録は従来どおり。
- タブが増えると幅を縮め、最小幅を超えれば横スクロールする。既存CSS変数を使い、アクティブなタブをツールバーの面につなげる。アニメーションは加えない。

### 9.3 見た目

- 色はCSS変数で定義し、`prefers-color-scheme` と手動切替（system / light / dark）に対応する。スライド自体はテーマの色のまま表示する
- 中立的なグレー基調、アクセント色は1色。アニメーションはなし（ホバーの色変化のみ）
- 編集中のブロックは細い枠で示し、選択中の要素にはアクセント色の2pxの枠を表示する。読み取り専用の要素はポインターを重ねると点線の枠と理由のツールチップを出す
- フォントはUIに `Segoe UI` / `Yu Gothic UI` を使う

#### 操作拒否理由コードと表示文言
| 理由コード | 日本語の表示文言 | 発生条件・用途 |
|---|---|---|
| `element-ambiguous` | 要素の位置を特定できないため操作できません | 要素の開始行・終了行や範囲を一意に決定できない場合 |
| `element-structure-changed` | 前後の要素の形が変わるため操作できません | 削除や挿入によってリストの結合など意図しないMarkdown構造の変化が起きる場合 |
| `element-heading-divider` | headingDividerが有効なため操作できません | 文書で headingDivider が設定されており、要素の削除や挿入が安全に行えない場合 |
| `element-readonly` | 読み取り専用または競合中のため操作できません | ファイルが読み取り専用状態、または外部変更の競合が未解決の場合 |
| `table-unsupported` | この形式の表は行・列を編集できません | 最上位以外の表、行頭・行末のパイプの欠落、セル数の不一致、エスケープしたパイプを含む表などの場合 |
| `table-header-row` | 見出し行は挿入・削除できません | 表の見出し行の上への行挿入、または見出し行単独の削除を行おうとした場合 |
| `table-last-column` | 最後の1列は削除できません | 表の列が1列のみの状態で列を削除しようとした場合 |
| `image-unsupported-alt` | 代替テキストの形式のため大きさを変更できません | 代替テキストにエスケープ文字が含まれるなど、安全に幅指定を置換できない場合 |
| `image-copy-failed` | 画像をコピーできませんでした | 画像ファイルの `images/` フォルダへの一時ファイル書き出しまたはリネームに失敗した場合 |
| `image-unsupported-type` | 対応していない画像の形式です | 選択されたファイルが対応拡張子（png / jpg / jpeg / gif / webp）以外の場合 |
| `bold-multiple-runs` | 複数の文字や装飾にまたがるため太字を変更できません | 選択範囲が複数の文字ランや装飾にまたがる場合 |
| `bold-partial` | 太字の一部だけは変更できません | 既存の太字の一部だけを選択している場合 |
| `bold-invalid-position` | この位置では太字にできません | 選択範囲が空で太字内でもない場合、Markdownの規則で太字として解析されない位置の場合、または選択中の要素で1か所でも太字として解析されない・検証に通らない場合 |
| `box-move-failed` | テキストボックスの位置を変更できません | 移動後の再解析・検証に通らない場合 |
| `box-convert-failed` | この要素は自由に配置できません | 既存要素の自由配置化後の再解析・検証に通らない場合、または headingDivider が有効な場合 |
